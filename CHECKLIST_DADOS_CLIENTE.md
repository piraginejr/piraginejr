# Checklist De Dados Para Solicitar Ao Cliente

## 1. Objetivo

Esta checklist serve para orientar o pedido de arquivos ao cliente quando ele puder enviar as primeiras informacoes.

A ideia e receber material suficiente para mapear:

- pessoas;
- membros;
- visitantes;
- arquivo morto;
- dizimos e ofertas;
- financeiro;
- plano de contas;
- centros de custo;
- One Page Report.

## 2. Arquivos Ideais

Solicitar, se existirem:

```text
1. Planilha principal de membros ativos
2. Planilha de visitantes ou frequentadores
3. Planilha de arquivo morto
4. Planilha de dizimos
5. Planilha de ofertas identificadas
6. Planilha de ofertas nao identificadas
7. Planilha financeira principal
8. Plano de contas
9. Centros de custo
10. One Page Report
11. Relatorios financeiros atuais
12. Modelo atual de recibo
```

Nem todos precisam existir. O importante e enviar o que a igreja ja usa hoje.

## 3. Informacoes De Pessoas

Colunas que podem aparecer:

```text
nome
cpf
rg
data de nascimento
telefone
whatsapp
email
endereco
bairro
cidade
uf
cep
estado civil
conjuge
filhos
status
membro
frequentador
visitante
data de batismo
forma de entrada
data de entrada
igreja de origem
ministerio
classe EBD
grupo familiar
pastor responsavel
observacoes
```

Pedir para o cliente nao reorganizar a planilha antes de enviar, salvo se houver dados sigilosos que ele deseje remover.

Motivo:

Precisamos ver como a igreja trabalha de verdade.

## 4. Arquivo Morto

Se houver arquivo morto, pedir:

```text
nome
cpf se houver
telefone se houver
data de saida
motivo
destino
transferido para qual igreja
falecido
desligado
observacoes
```

Possiveis situacoes:

```text
transferido
desligado
afastado
falecido
mudou de cidade
mudou de denominacao
sem contato
```

## 5. Dizimos E Ofertas

Pedir planilhas que mostrem:

```text
data
competencia
doador
cpf do doador se houver
tipo: dizimo, oferta, campanha
valor
forma de recebimento
conta ou caixa
observacoes
recibo emitido
```

Importante:

Se a igreja tiver dizimos/ofertas em varias abas por mes, enviar o arquivo completo com todas as abas.

## 6. Financeiro

Pedir a planilha financeira principal, mesmo que seja complexa.

Colunas importantes:

```text
data
competencia
vencimento
pagamento
descricao
fornecedor
cliente
receita
despesa
valor
plano de contas
centro de custo
conta bancaria
status
documento
observacoes
```

Se houver diario contabil ou diario gerencial, enviar a planilha como esta.

## 7. Plano De Contas

Pedir, se existir:

```text
codigo
nome da conta
conta pai
nivel
tipo
grupo
se aceita lancamento
```

Tambem perguntar:

```text
Quais contas entram como receitas operacionais?
Quais entram como outras receitas?
Quais entram como despesas operacionais?
Quais entram como despesas orcamentarias?
Quais entram como despesas extraorcamentarias?
```

## 8. Centros De Custo

Pedir, se existir:

```text
codigo
nome
departamento
ministerio
projeto
unidade
status
```

Perguntas importantes:

```text
Centro de custo e independente do plano de contas?
Um lancamento pode ter mais de um centro de custo?
Existe rateio?
Centro de custo representa ministerio, departamento, projeto ou unidade?
```

## 9. One Page Report

Pedir:

```text
planilha do One Page Report
abas auxiliares usadas pelo One Page
formulas preservadas
relatorio de um periodo ja fechado
se possivel, um PDF ou print do modelo usado pela diretoria
```

Perguntas:

```text
Qual periodo o One Page costuma analisar?
Quais indicadores sao obrigatorios?
Quais numeros precisam bater exatamente?
Quais indicadores sao decisorios?
Quais metas aparecem no relatorio?
Quem usa esse relatorio?
```

## 10. Recibos

Pedir:

```text
modelo atual de recibo
texto padrao
logo se houver
dados legais da igreja
assinatura se houver
regra de numeracao
periodo coberto
se recibo e anual, mensal ou por contribuicao
```

## 11. Cuidados De Privacidade

Como os dados podem conter CPF, endereco, telefone e contribuicoes, orientar o cliente:

```text
Enviar apenas por canal seguro.
Nao enviar em grupos.
Se preferir, enviar uma copia anonimizada para a primeira analise.
Nao alterar a estrutura original da planilha.
Remover apenas dados que a igreja nao queira compartilhar neste momento.
```

Para primeira analise, se o cliente estiver receoso, pode enviar:

```text
arquivo com 20 a 50 linhas reais anonimizadas
ou arquivo completo com nomes/CPF mascarados
```

## 12. Perguntas De Contexto

Fazer ao cliente:

```text
Quantas pessoas existem no cadastro ativo?
Quantas pessoas existem no arquivo morto?
Quantas unidades/congregacoes existem?
Quem alimenta as planilhas?
Com que frequencia os dados sao atualizados?
Quais relatorios sao mais importantes?
Quais dores principais existem hoje?
Existe retrabalho mensal?
Existe problema de duplicidade?
Existe necessidade de recibos individuais?
Existe prestacao de contas por centro de custo?
O One Page e usado por quem?
```

## 13. Ordem Ideal De Envio

Se o cliente nao puder enviar tudo de uma vez, pedir nesta ordem:

```text
1. Planilha de membros ativos
2. Arquivo morto
3. Planilha de dizimos/ofertas
4. Planilha financeira principal
5. Plano de contas e centros de custo
6. One Page Report
7. Modelo de recibo
```

## 14. Mensagem Curta Para O Cliente

Texto sugerido:

```text
Para avaliarmos a implantacao do sistema, precisamos entender como a igreja organiza hoje seus dados. Voce pode enviar as planilhas usadas atualmente, sem reorganizar o formato, pois a estrutura original nos ajuda a mapear a importacao.

Se houver dados sensiveis, pode enviar inicialmente uma copia anonimizada ou uma amostra com algumas linhas. O ideal e receber planilhas de membros, arquivo morto, dizimos/ofertas, financeiro, plano de contas, centros de custo, One Page Report e modelo de recibo, se existirem.
```
